# Evidence Rules

## Source Priority
1. User-approved Career Evidence Bank.
2. New facts explicitly confirmed by Ravi.
3. Master resume.
4. Recognition artifacts and supporting documents.
5. Public product/company documentation for contextual descriptions only.

Public product documentation may explain what a platform does. It must not be used to claim Ravi personally performed every platform capability.

## Evidence Labels
- A: Direct evidence.
- B: Supported but incompletely documented.
- C: Transferable, not equivalent.
- D: No evidence.
- X: Hard conflict.

## Known Boundaries
- Cross-functional leadership is supported; direct-report management is not.
- Mentoring approximately 15–17 engineers is a user estimate.
- Approximately 3–5 interviews and hiring recommendations are supported; final hiring authority is not.
- Schedules, dependencies, risks, and release planning are supported; staffing/resource allocation is not established.
- Budget and formal performance management are unsupported.
- Deployment coordination is supported; CI/CD platform architecture is not.
- AWS production involvement is supported; ownership of the complete cloud architecture is not.
- GenAI/cloud modernization PoC evaluation is resume-supported; production AI-platform delivery is not.

## Metric Rules
Use approximate language for estimates. Metrics from the resume that lack measurement context should be flagged for validation before relying on them heavily in interviews.
